# R106 Balanced Scalar/Publication Pipeline

Date: 2026-08-10  
Status: rejected at frozen cold-construction gate; archived and removed

## Question

Can one architecture-wide pipeline combine the exact complete scalar Tier-0
with prompt asynchronous-region publication so that the interpreter is faster
while code is cold and does not outrun code generation once regions are in
flight?

This is not permission to retry R105 alone or to sweep a selector. R105 remains
rejected under D100. R064 remains rejected as a standalone scheduler change.
R106 treats their exact mechanisms as one indivisible runtime design and will
either promote that one design through every product gate or remove both.

## Mechanistic basis

R105 held guest work fixed and improved Boot `1.0588x`, but its candidate
executed median `1.0122x` and `1.0555x` as many residual interpreter
instructions in Compile and Python. It correspondingly measured `0.9803x` and
`0.9792x` elapsed speedups. This is consistent with faster cold execution
advancing through guest work while asynchronous page regions remain pending.

R064 tested the exact complementary lifecycle on a same-Wasm basis under the
public one-pump cadence. Returning at a quantum boundary while a region was
pending reduced median residual interpreter retirement to `0.8944x` in Compile
and `0.6269x` in Python. It improved those rows `1.0494x` and `1.0544x`, while
costing Boot `0.9758x`. The independent median-product projections for the
frozen combination are therefore Boot `1.0333x`, Compile `1.0287x`, and Python
`1.0324x`.

Those projections are admission evidence only. They come from different
historical artifacts and earn no performance credit. The deterministic proof
`target/bench/r106-balanced-scalar-publication/opportunity.json` must validate
the exact source reports and the opposing interpreter-retirement mechanisms
before implementation. It passes all ten frozen checks with SHA-256
`aaf86c4afff5764098f4370a7322ec69cdd519167a429d2ffd42af251a6eae48`.

The control is the clean executable-R085-equivalent source build:

- Wasm `d9f686a9ce4f54734f310cf5789f900af0c9b7067539e0251c429f376dd3df6d`;
- core source `aec4b31434a6c3940802463954ee8117313a2dda7c5d98a4d99732aa70a0c2ce`;
- Wasm source `1da35e70bc9c957fd184f1cd9e6772d6d0a7380398aa7fc17369581b53036339`;
- loader `2cbb264f4dac9d32e96254a4b12961c84a862e2bf3b6a5adcba248d2ad7b4385`;
- R087 public one-slice cadence; and
- modern Linux 6.12.7 / Alpine 3.24.1 only.

The sole candidate contains exactly:

1. R105's byte-exact architecture-defined scalar driver: complete ordinary
   RV64I/M integer, control, scalar load/store, and integer RV64C families;
   local PC/retirement carry; exact interrupt polling; authoritative slow
   fallback for uncommon families.
2. R064's exact pending-publication lifecycle: after each of the two existing
   `page_policy_issue` sites in `run_system_jit`, return from the current host
   call when and only when an async region remains in `PENDING_SB`. The public
   scheduler performs its unchanged event-loop yield and calls again.

There is no guest PC, opcode frequency, privilege, workload, engine, elapsed
time, module count, coverage, phase, or benchmark selector. There is no new
threshold or quantum. For the first causal candidate both mechanisms are
default-off behind two proof setters in one identical Wasm. Control is
scalar-off/publication-off; candidate is scalar-on/publication-on. Component
legs are forbidden, so no result can select one after timing.

## Correctness, shape, and cold gates

Before timing:

1. repeat R105's exhaustive scalar/RVC, M/A/FP, system memory, Sv39/MPRV, WFI,
   T2, public/Worker, and direct/OpenSBI modern Linux candidate-on matrix;
2. verify pending publication changes only host-call boundaries, never guest
   retirement, interrupt/device service, policy state, generated bytes, or
   publication validation;
3. disassembly must show exactly one pending test after each policy-issue site
   in both concrete system drivers, matching archived R064 topology;
4. imports must remain unchanged and exports may add only the two proof
   setters; and
5. seven alternating fresh-process main-Wasm construction pairs may regress
   by at most `1.05x`; bytes and CODE size are diagnostic only.

Any repair may restore these exact semantics or add a regression test, but may
not move a boundary, change a family, or add a knob after timing starts.

## Frozen native causal gate

Run seven alternating fresh-process pairs for Boot, Compile, and Python on
CPUs 8--15. Both legs use the one immutable candidate Wasm, exact modern
inputs, production policy, and one-slice cadence. All identities, outputs,
fixed work, generated execution, host spread (`<=1.10x`), sample spread, and
order proofs must pass.

R106 advances only when:

- Boot and Compile paired-median speedups are each at least `1.01x`, with
  paired-bootstrap 95% lower bounds at least `1.00x`;
- normalized Boot and Compile MIPS each reach `1.01x`;
- Python paired median is at least `0.99x` and its interval does not establish
  regression;
- candidate/control residual interpreter-instruction paired medians are at
  most `1.00x` for Compile and Python; and
- candidate/control asynchronous availability-latency paired medians are at
  most `1.00x` for Compile and Python.

There is no extension, replacement, historical pooling, component leg, or
retry.

## Product escalation

If and only if native causality passes, build one clean default-on artifact
with both proof setters removed. Repeat strict correctness and five native
Boot/Compile/Python pairs under the same thresholds. Then run, in order:

1. seven fresh alternating Chrome execution-Boot pairs, requiring `>=1.01x`
   with lower bound `>=1.00x`;
2. the exact R094-qualified 32 MiB WANIX shell, `python /shared/bench.py`,

verified improvements in both open Boot and Compile rows, and no protected row

all evidence, remove both mechanisms, and restore exact `d9f686a9...`.

## Result

The deterministic opportunity proof passed all ten checks. The immutable
default-off candidate is `6571795ef19c...`; subtracting the exact publication
declaration and two checks recovers archived R105 Wasm source byte-for-byte.
Its imports are unchanged, its only added exports are the two proof setters,
and disassembly finds two pending-flag loads in each concrete system driver,
matching archived R064. Candidate module/CODE growth is 38,127/36,807 bytes,
recorded only as diagnostic information.

All pre-timing correctness gates passed with both switches enabled: 35 core,
53 DBT, 76 system, and four Wasm units; raw Wasm smoke; 100 randomized scalar
programs; M/A/FP and translated-memory differentials; Sv39/MPRV; WFI; T2
atomic, multi-entry, and lifecycle tests; public/Worker APIs; and fresh direct
and OpenSBI Linux 6.12.7 boots reaching Alpine 3.24.1 while executing generated
code.

The first allowed performance gate then failed. Seven alternating fresh-process
construction pairs measured control/candidate medians of 12.227977/12.853591
ms, or `1.0511625x` candidate/control, just beyond the frozen `1.0500000x`
limit. The paired-ratio median was `1.0515631x` with a wide
`[1.0102710,1.1289065]` interval. The point rule was frozen before this result,
so R106 receives no rerun, threshold relaxation, or native timing. This is not
a small runtime gain rejected: no Boot/Compile/Python causal result exists.

Evidence is immutable under
`target/bench/r106-balanced-scalar-publication/`; opportunity, shape, and cold
reports are `aaf86c4afff5...`, `f5079f0b5b4f...`, and `b2978baeaf18...`.
Both mechanisms and their live diagnostic plumbing were removed. Core/Wasm
source, release Wasm, and loader are restored exactly to `aec4b31434a6...`,
`1da35e70bc9c...`, `d9f686a9ce4f...`, and `2cbb264f4dac...`; restored units,
raw Wasm, public/Worker, and both modern Linux paths pass.

The near-boundary noisy result exposes a protocol-design issue without changing
this decision: future cold gates must prospectively state whether they use a
point non-inferiority limit, an interval rule, or an amortized end-to-end cost.
That choice cannot be made after observing a candidate.
