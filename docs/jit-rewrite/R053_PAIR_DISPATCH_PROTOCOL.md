# R053 Exhaustive Pair-Dispatch Protocol

Status: complete; rejected at engine-shape gate  
Date: 2026-08-08

## Question

Can an architecture-complete, precompiled two-instruction handler tier remove
enough interpreter dispatch cost to justify touching the production emulator?
This differs from R047: R047 selected a small Boot-ranked exact-triple library;
R053 contains every ordered pair of the 62 normalized scalar operation kinds
and has no trained or workload-selected handler population.

## Existing opportunity bound

The retained exact R047 traces show that fixed-width pairing can remove 42.79%
of all Boot dispatches, 43.77% of Compile dispatches, and 46.30% of Python
dispatches. Those are optimistic dispatch-count bounds, not wall-time results.
They merely admit this isolated engine-shape test.

## Frozen comparison

`emit_pair_dispatch_corpus.rs` deterministically emits two standalone modules:

- `single.wasm`: 62 handlers and one indirect dispatch per scalar operation.
- `pair.wasm`: all 3,844 ordered handlers and one indirect dispatch per two
  scalar operations.

Both consume the same balanced 4,096-pair selector cycle, execute identical
state transformations, and return identical checksums. The 62 operation
shapes cover 16 inexpensive integer lowering families; this test deliberately
does not claim to reproduce RV64 memory, trap, or control semantics. It is a
necessary backend-shape screen, not sufficient evidence to ship a tier.

The harness regenerates the corpus twice, validates and hashes the bytes,
checks exact state at five operation counts, and uses seven alternating paired
fresh Node/V8 processes. Compile, instantiate, first call, warm calls, and
seven steady samples per process remain separate.

## Predeclared decision

Admit a production prototype only if all of the following hold:

1. generated bytes are deterministic and valid;
2. single and pair state/checksums are exact and stable;
3. paired median steady throughput is at least 1.25x single dispatch;
4. pair-module median compile plus instantiate time is at most 100 ms; and
5. its paired cold-construction delta is at most 100 ms.

Failure closes the exhaustive function-per-pair representation without a
handler subset, operation-popularity selector, threshold sweep, or production
scorecard. Passing only licenses an architecture-general, default-off
production prototype followed by the normal correctness and same-Wasm A/B
gates; it is not itself a performance promotion.

## Result

The frozen report is `target/bench/r053-pair-dispatch-corpus.json`. Seven
alternating paired fresh Node 26.5/V8 14.6 processes measured the single tier
at 116.367 million operations/s and the exhaustive pair tier at 102.191
million operations/s. Pair/single throughput was 0.879x with a deterministic
bootstrap median interval of 0.878-0.882: pairing regressed the isolated kernel
12.1% despite halving loop iterations and indirect calls.

Both modules regenerated byte-identically, validated, and matched every state
checksum. Pair cold construction was only 1.068 ms, a paired increase of 0.847
ms, so the rejection is not caused by the cold-cost limit. The broad 3,844-way
polymorphic indirect-target execution shape outweighs the removed dispatch in
this corpus. `admitProductionPrototype` is false; production was not changed.
