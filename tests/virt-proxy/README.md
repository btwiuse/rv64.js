# virt-proxy — full Debian networking integration

This is the heavier companion to `tests/virt-smoke`. It boots the modern
OpenSBI + Linux `virt` machine from a real Debian riscv64 ext4 image and checks
the complete user-facing path:

1. Linux seeds `CLOCK_REALTIME` from the emulated goldfish RTC.
2. `udhcpc` configures virtio-net from the in-process DHCP server.
3. Debian's real curl/OpenSSL build starts successfully.
4. curl sends an HTTP request to `10.0.2.2:8080`, and `rv64-vboot --proxy`
   forwards it to a temporary loopback origin.
5. curl POSTs a genuinely chunk-framed request, which the proxy decodes before
   forwarding it with a reconstructed content length.
6. The guest mounts the fixed `rv64-proxy` 9p tag during boot and installs the
   exact ephemeral public CA generated by this proxy instance.
7. curl reaches the real `example.com` through the proxy over plaintext HTTP.
8. curl reaches `https://example.com` without a per-command `--cacert`; its
   verbose certificate trace identifies `rv64.js ephemeral proxy CA` as the
   issuer and confirms successful verification. Native egress independently
   validates example.com's real certificate on its upstream rustls connection.

Build the persistent guest once, then run the test:

```sh
nix develop -c tests/vs-v86/mk-debian-rootfs.sh target/bench
nix develop -c tests/virt-proxy/run.sh
```

The default disk is `target/bench/deb-riscv64.ext4`; override it with
`DEBIAN_DISK=/path/to/image`. The kernel and OpenSBI come from the flake. The
kernel's virtio block/net/9p, ext4, and packet-socket support are built in
because this intentionally small root filesystem does not carry a kernel
module tree. This test intentionally requires external access to `example.com`.

This test is manual rather than part of `tests/run-all.sh`: creating the guest
downloads Debian packages, the first kernel realization is expensive, and a
full Debian boot is much slower than the tiny initramfs smoke test.
