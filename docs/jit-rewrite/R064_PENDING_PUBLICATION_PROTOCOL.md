# R064 Pending-Publication Protocol

## Hypothesis

R063 proves that async page modules can remain unavailable while the rewrite
runtime executes long host slices. A scheduler-wide event-loop turn after every
2,000,000-instruction pump improved Compile 1.060x and Python 1.246x, but did
not advance Boot. R064 tests the narrower product mechanism: after a page
module is issued, return from `run_system_jit` at the next interpreter/JIT
quantum boundary while and only while `PENDING_SB` is non-empty. The public
browser scheduler then yields naturally; a synchronous embedding retains full
control and may call back immediately.

This is architecture-wide lifecycle behavior. It does not change guest code,
hotness, thresholds, module geometry, generated bytes, or opcode handling.

## Frozen comparison

The prototype starts from accepted R054 Wasm SHA-256
`4160333352b18b233b3bba69858bfdc8b83474d94f2283ff49bf6a8b538ea69d`.
It is default-off and controlled by `jit_set_yield_on_pending(0|1)`. Both A/B
legs use the same candidate Wasm and the R063 fair diagnostic cadence
`SCORECARD_V2_YIELD_EVERY_PUMP=1`; the only causal difference is
`SCORECARD_V2_YIELD_ON_PENDING=0|1`.

## Gates

1. Rust formatting, all `rv64-core` unit tests, worker syntax, Wasm smoke, JIT
   differentials, and modern Linux direct/OpenSBI tests must pass with the
   candidate both off and on where applicable.
2. Exact guest output/checksums and input hashes must match. Fixed-work rows
   must retain equivalent total guest retirement, allowing only documented
   timer/console scheduling noise outside timed guest work.
3. Run three alternating fresh-process pairs for Boot, Compile, and Python.
   Continue to five only if Boot or Compile reaches a paired median 1.10x, its
   lower interval is at least 1.00x, and neither other row falls below 0.90x.
4. A promoted candidate must also pass the browser `/shared/bench.py` guard
   with no phase regression of 10% or more, followed by the complete
   authoritative three-way scorecard.
5. If the screen misses the advancement gate, remove every production switch
   and restore the exact R054 artifact. Preserve only the protocol and report.

## Result

The valid three-pair report is
`target/bench/r064-pending-publication-screen/config-ab-2026-08-09T02-08-11-937Z.json`;
host-probe spread was 1.038 and all input/output fingerprints matched. Paired
candidate speedups were:

- Matched Boot: 0.976x, interval `[0.969, 0.987]`;
- Compile STEADY: 1.049x, interval `[1.004, 1.058]`;
- Python STEADY: 1.054x, interval `[1.037, 1.149]`.

The mechanism worked as designed but lacked leverage. Compile's recorded async
availability latency fell from roughly 174-180 ms to 8 ms; Python's fell from
2.36-2.47 seconds to 0.43-0.50 seconds, and Python interpreter retirement fell
from 31.3-34.1 million to about 20.3 million instructions. Those changes
produced only 4.9% and 5.4% wall-time gains and slightly regressed Boot. R064
therefore fails its predeclared 10% advancement gate. The runtime switch and
all source hooks were removed; its candidate artifact remains archived only as
evidence.
